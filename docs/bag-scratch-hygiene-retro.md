# BAG Scratch-Hygiene Retroactive Audit

Audit of every BAG trial under `bench/jobs/2026-05-*` whose
`agent/bag-traces/.bag/runs/<id>/autonomous-trace.json` exists, run through
the new `auditScratchHygiene` helper introduced in
`src/scratch-hygiene.ts`. The same heuristics now feed the pre-submit
self-check auditor as a `[Pre-submit hygiene scan]` system-context block,
so the numbers below reflect what the live gate will see going forward.

Source data: 225 BAG trace files spanning ~50 job dirs (May 1 – May 2).

## Headline numbers

| signal | wins flagged | rate |
|---|---|---|
| any uncleaned `/tmp/` write at submit | 71 / 179 | **39.7 %** |
| Python Traceback / panic / segfault present anywhere in trace | 51 / 179 | **28.5 %** |
| run of consecutive non-zero exits never re-run successfully | 68 / 179 | **38.0 %** |
| Traceback in the LAST 4 bash calls before submit | 0 / 179 | 0.0 % |

The "tb-last4 == 0 %" line is interesting — agents reliably push tracebacks
out of the tail before submitting (typically by running a final `ls` or
`cat`), but the deeper signal is the `tb-anywhere` column which catches
recoveries that papered over a real crash. The current self-check gate
sees ONLY the last 8 calls, so it would miss most of those wins entirely
without the structured signal injection.

## Headline read

- **`build-cython-ext` is 100 % traceback-recovered**: 16 / 16 wins contain at
  least one Python Traceback before declaring complete. This corroborates
  the deep-dive memo (`docs/bag-successful-runs-deep-dive.md`) finding that
  every win in this family is a recovery from a crash, not a clean solve.
- **`chess-best-move` and `qemu-startup` are >85 % consecutive-failure
  recoveries**: the agent fails the same operation multiple times in a row
  before stumbling into a passing variant. A stricter gate that demands a
  successful re-run of the LAST failing command would intercept those
  trials and force a self-check round.
- **`log-summary-date-ranges` (72 %), `qemu-startup` (100 %), and
  `qemu-alpine-ssh` (100 %)** leak scratch into `/tmp/` with no cleanup.
  Today's verifier doesn't care; a clean-room verifier rejects all of
  them. That is **40 trials** of "lost reward" if the verifier upgrades.
- **`fix-code-vulnerability` is the cleanest family**: 0 % `/tmp/` leak,
  but 71 % of wins contain a Traceback somewhere — those are the
  "scope failing test, fix, re-run" cycles flagged in the deep dive
  as the only HEALTHY recovery pattern (16/21 fail-then-pass cases
  cited in the memo).
- **`polyglot-c-py` and `regex-log`** are short and clean (4.5 % and
  3.6 % traceback rates respectively); these families aren't exercising
  the new gate signals.

## Brittleness exposure

Of the 179 wins, **88 (49.2 %) have at least one of: a `/tmp/` leak, a
non-zero exit chain, or a Traceback in trace**. That's roughly half of
all wins potentially at risk under stricter post-submit verification.

Concretely, if a clean-room verifier upgrades to:
1. Reject any submit that left files under `/tmp/`: **71 wins lose reward**
   (-39.7 % of the leaderboard).
2. Reject any submit whose last 4 bash calls had a non-zero exit chain
   never resolved: **68 wins lose reward** (-38.0 %).
3. Reject any submit whose trace contains an unresolved Traceback: **51
   wins lose reward** (-28.5 %).

These overlap heavily — the union is 88 (49.2 %) and only 91 wins are
clean across all three signals. The new self-check failure modes 6 and 7
do not block these wins today (the auditor is fail-open and the LLM has
to agree); they SURFACE the pattern via structured `[Pre-submit hygiene
scan]` context so the auditor can cite specific paths and signatures
when deciding whether to fire.

## Methodology

For each `autonomous-trace.json` we reconstruct the bash trace by pairing
`tool_call` and `tool_result` entries (same algorithm as
`autonomous-coding-turn.ts:collectBashTraceTail`), then run
`auditScratchHygiene` over the full reconstructed tail. "wins" are
trials whose `result.json` reports `verifier_result.rewards.reward >= 1.0`.
Family is derived from the directory name prefix (everything before
`__`).

The script is `/tmp/retro_audit.ts` (kept out of the repo because it's a
one-shot analysis tool, not production code). To regenerate:
`bun /tmp/retro_audit.ts`.
